# Companion Android build

[Deutsch](../docs/COMPANION.md) · [English](../docs/COMPANION.en.md)

Companion 1.2.0 is the current version with versionName 1.2.0 and versionCode 12. 1.2.0 animates page transitions on the device: it announces the protocol capability `xfade1` in `hello`; the PC then sends a `transition` text message followed only by the target frame, and the app draws HUD scan, slide or fade in step with the screen refresh (protocol: `docs/COMPANION-PROTOKOLL.md`). Older apps without `xfade1` keep receiving server-rendered intermediate frames. On TVs and large displays (from about 1.5 MP or `FEATURE_LEANBACK`) frames are copied to hardware bitmaps on the decode thread, so the texture upload no longer stalls drawing. Measured with an isolated test app on a Redmi 8 and a BeyondTV, see `docs/ANIMATION-RUNDEN.md`; live content on the TV stays at about 15 frames/s (1080p decoding). The debug build uses the package suffix `.hudtest` (`de.fuchslabs.display.hudtest`) so it can be installed next to the real Companion without touching its pairings. The protocol is extended backward-compatibly (`xfade1`); the application ID of the release build is unchanged. 1.1.2 made the display smoother: decoded bitmaps are reused (inBitmap pool; a replaced bitmap is reused only after the frame that replaced it has finished drawing) and up to two decoded frames are shown one per screen refresh (Choreographer) instead of only the newest; on a Redmi 8 about 59 instead of 52 displayed frames/s with hardly any janky frames, at most one frame (~16 ms) of extra latency. Measured with an isolated debug test app on a Redmi 8, see `docs/ANIMATION-RUNDEN.md`. Since Companion 1.1.0: dark default design and opt-in automatic mode using the paired PC's mDNS announcement. 1.1.1 fixes 1.1.0 defects (bounded frame hand-over, TCP confirmation before automatic mode closes the display, locking only an automatically opened foreground display, re-pairing into an open display, discovery restart); it was validated by JVM tests and a debug compile only, not on devices. It includes the earlier API 36/setup-insets changes and keeps the protocol and application ID. `app/build.gradle.kts` declares the same values. Permissions, phone locking, TV limits and test limits: [automatic-mode guide](../docs/COMPANION.en.md#automatic-mode-companion-110). The Redmi 8 acceptance over USB tethering on 27 October 2026 was for predecessor 0.2.1-preview (versionCode 3), not this version.

Use JDK 21 and Android SDK 36. Run `gradlew.bat :protocol:test :app:assembleDebug` for development. To sign a release, set `SCREENBUDDY_SIGNING_PROPERTIES` to an absolute properties-file path outside the checkout, then run `gradlew.bat :app:assembleRelease`. The properties must contain `storeFile` (absolute path, forward slashes), `storePassword`, `keyAlias` and `keyPassword`. Never put secrets in command arguments or the repository. Without this environment variable, release builds remain unsigned and must not be distributed.

Verify `app/build/outputs/apk/release/app-release.apk` using SDK Build Tools `apksigner verify --verbose --print-certs`, and record its SHA-256 and certificate fingerprint. Back up the private keystore and its passwords securely outside this machine before publication; future APK updates require the same key. No signing material is included here.

The new release certificate differs from the old debug certificate. Android cannot install it as an update over that debug APK. Do not uninstall automatically: this removes local app data and pairings. Keep the old APK available, agree on the device migration, then pair again and test landscape/portrait output, touch, disconnect and reconnect. Previous 0.2.0 device results do not establish acceptance of 0.2.1.

Seit 1.1.0/1.1.1: dunkles Standard-Design und optionale Automatik über die mDNS-Ankündigung des gekoppelten PCs. 1.1.1 behebt Fehler aus 1.1.0 (begrenzte Bildübergabe, TCP-Bestätigung vor dem Schließen durch die Automatik, Sperren nur einer automatisch geöffneten Anzeige im Vordergrund, erneute Kopplung in eine offene Anzeige, Neustart der Suche); geprüft nur mit JVM-Tests und Debug-Kompilierung, nicht an Geräten. Die früheren API-36-/Inset-Änderungen sind enthalten; Protokoll und App-ID bleiben erhalten. `app/build.gradle.kts` nennt dieselben Werte. Für den signierten Build zeigt `SCREENBUDDY_SIGNING_PROPERTIES` auf eine private Properties-Datei außerhalb des Repositorys. Ohne diese Variable bleibt der Release-Build unsigniert. Die vier erforderlichen Felder und die Prüfkommandos stehen oben.

Den privaten Keystore und seine Passwörter vor Veröffentlichung zusätzlich sicher außerhalb dieses Rechners sichern. Alle künftigen Updates brauchen denselben Schlüssel. Migration abstimmen, danach erneut koppeln und Bild, Ausrichtung, Touch sowie Trennen und Wiederverbinden am Gerät prüfen.

API-36 migration: AGP 8.10.1 / Gradle 8.11.1. Setup handles system bars, display cutouts and the keyboard using window insets. Android 8 (minSdk 26) remains supported. Build signed delivery APKs with `./Build-Companion.ps1`; no Play upload is performed. Future AAB creation uses `:app:bundleRelease`, subject to separate Play preparation and review.
